# Learning Schedule kill switches and application rollback

1. Confirm the target deployment and database identity with the incident lead. Capture a sanitized snapshot and record whether either database gate is already OFF.
2. Through the existing privileged deployment/database control path, disable `study_notification_dispatch_control` and commit. In an approved SQL session the targeted update is `UPDATE public.study_notification_dispatch_control SET enabled = false WHERE singleton;`. Confirm OFF with `verify-gates`. The update can wait for an in-flight claim or handoff transaction. Wait for commit confirmation before treating the fence as active.
3. Disable `STUDY_REMINDER_REAL_SEND_ENABLED` on the running worker deployment through its approved configuration path. Verify the effective setting on the running instance. Gate OFF fences new handoffs after commit. A submission authorized by an already committed handoff may still reach the provider. Preserve its outcome and hold uncertainty.
4. If Sweep must stop, commit `UPDATE public.ls_missed_sweep_control SET enabled = false WHERE singleton;` through the privileged control path. Verify OFF and compare session/audit counts. Allow in-flight work to settle before comparing.
5. If health is unavailable, record state as unknown. Confirm gate state independently through the authorized database path and stop worker execution through its control plane if the fence cannot be established.
6. Roll back only the application artifact after confirming compatibility with the current schema and retained data. Keep migration history and schema in place. Record the source and target artifact SHAs, migration head and sanitized row/count checks. Stop if compatibility or gate state is unverified. Never drop Learning Schedule tables or reverse production migrations as an incident shortcut.
7. Check health on the restored app, both persisted gates, effective real-send setting, row invariants and held attempts. Re-enable only with incident approval and monitoring in place. Uncertain attempts must stay held after re-enable.
