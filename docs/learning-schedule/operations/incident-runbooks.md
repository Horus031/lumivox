# Learning Schedule incident runbooks

Run the diagnostics from a trusted operator host. Set `LEARNING_SCHEDULE_OPS_ORIGIN` to the verified application origin and inject `LEARNING_SCHEDULE_MONITORING_SECRET` through the approved secret store. The CLI calls the existing internal health endpoint. It emits aggregate JSON and exits nonzero on denied access or unavailable diagnostics. Keep repeated snapshots in time order and treat a capped count as at least 1,001. Share only aggregate counts, timestamps, status codes and sanitized deployment references. Use the [recovery matrix](recovery-decision-matrix.md) for any state change.

| Incident and trigger | Diagnostics | Safe action and stop conditions | Validation and escalation |
| --- | --- | --- | --- |
| `pending_due_backlog`. Dispatch enabled and oldest due age exceeds 5 minutes. | Run `inspect-queue` and `verify-gates`. Compare age and count across polls. Check trusted worker execution and recent sanitized outcomes. | Restore the approved worker path only after verifying the deployment identity, gates, and relevance checks. Leave Dispatch OFF during a deliberate hold or while the cause is unknown. Never force due dates or bypass consent. | Oldest due age and count decrease without increased uncertain attempts. Escalate to the worker on-call if age grows or the worker cannot be restored. |
| `expired_leases`. Present in two consecutive snapshots. | Run `inspect-queue` and `inspect-uncertain`. Through restricted incident access, establish whether the matching attempt reached durable handoff. | Use the bounded lease reconciler through the trusted boundary after stopping competing work when required. Uncertain or submitting attempts go to hold. Stop if the lease is active or the scope cannot be established. | Check lease count, state transition and provider submission delta. Escalate if leases reappear or a post-handoff attempt has no trustworthy outcome. |
| `uncertain_resend_submission`. One or more uncertain attempts. | Run `inspect-uncertain`. Through restricted incident access, correlate immutable handoff facts with a trusted provider response or verified signed webhook. | Hold. Record confirmed acceptance only through the authorized outcome command with matching handoff token, payload fingerprint and provider message ID. Never edit `study_notification_deliveries` directly. Absence of a provider record is insufficient evidence for retry. | Verify the original attempt and provider message correlate, and uncertainty clears through the controlled path. Escalate ambiguous, conflicting or unavailable evidence to incident lead and provider support. |
| `unmatched_webhooks`. Oldest unmatched receipt exceeds 15 minutes or count grows. | Run `inspect-webhooks`. Verify signature acceptance in sanitized ingress logs, receipt persistence and correlation to the original message and recipient fingerprint through restricted access. | Allow normal correlation after trustworthy acceptance is recorded. Hold unverified or mismatched events. Never forge receipts or replay unsigned payloads. | Check unmatched count/age and final correlated state. Escalate sustained increases, signature failures or any recipient mismatch. |
| `missed_sweep_backlog`. Backlog grows across three increasing uncapped snapshots with Sweep enabled. | Run `snapshot` and `verify-gates`. Check the 60-minute grace window, root Task and active Schedule eligibility, scheduler logs and lock waits via restricted DB observability. | Restore the approved Sweep path only with known gate state and a healthy scheduler. Do not mark Sessions missed by editing rows or forcing the grace cutoff. | Compare backlog and audit deltas after the next run. Escalate sustained lock contention or missing audit events. |
| `focus_launch_conflicts`. Unexpected growth in HTTP 423 or a failure to recover from a conflict. | Run `snapshot` for active Focus count. Compare sanitized launch codes, timing and lock evidence. An isolated 423 with an active Focus session is expected. | Use the existing recovery flow for the active session. Do not clear locks manually or force a second session. Keep the incident open if 423 persists without a corresponding active session. | Verify one active Focus session and one persisted attribution after recovery. Escalate persistent conflicts, duplicate rows or unexpected 5xx to the Focus on-call. |

From the repository root, use `node scripts/learning-schedule-ops.mjs <command>`. A health failure means the gate state is unknown. `verify-gates` reports persisted Dispatch and Sweep gates. Verify the real-send setting separately on the actual running deployment.
